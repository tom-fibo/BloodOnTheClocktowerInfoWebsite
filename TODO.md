## Night communication MVP (room + roster + private ST/Player messaging)

- Status: **implemented**, not yet fully tested & functional (basic page load confirmed manually; full multi-device roster/secret-message flow still needs to be run through, see MAINTENANCE.md verification checklist).
- Scope: Storyteller hosts a room via a shareable code; Players join with a display name; everyone sees a live, ordered player roster; Storyteller can secretly message any one Player; a Player can secretly message only the Storyteller. Peer-to-peer via Trystero (WebRTC), no backend.
- Not yet done / explicitly deferred: offline/no-internet fallback, GitHub remote + Pages deployment (manual step, not yet performed) — this MVP is comms plumbing only; actual game content (characters, night order, votes, etc.) is covered under "Current plans for full website" below.
- **Persistent reconnect / seat reclaim** — status: **implemented**, not yet tested & functional. A per-room localStorage token is sent with `hello`; the Storyteller matches it back to the player's existing seat instead of creating a new one. Needs a real reload-mid-game test across devices.
- **Storyteller disconnect resilience** — status: **implemented**, not yet tested & functional. The Storyteller's room state (seats, characters, script, audit log, notes) persists to localStorage and restores on reload/crash — same-browser recovery only, not cross-device. Needs a real "reload the Storyteller's tab mid-game" test.
- **QR code join link** — status: **implemented**, tested & functional. Storyteller's room header has a "QR" toggle encoding a join URL (`?join=CODE`); `join-setup` pre-fills the code from that URL. Manual code entry still works as before. Uses the new `qrcode-generator` dependency (see MAINTENANCE.md). First-round testing found the toggle button did nothing (a CSS specificity bug — a later `display: flex` rule silently beat the `.hidden` utility); fixed with a combined `.qr-container.hidden` selector.
- **Auto-rejoin last session on reload** — status: **implemented**, not yet tested & functional. A reload (intentional or accidental) now re-navigates to whichever room screen (Storyteller/Player) this browser was last in, via a `localStorage`-saved `{screen, roomCode, selfName}` — the actual rejoin correctness still comes from the reconnect-token/host-state mechanisms above, this just gets the app to *try* rather than dumping the user at the landing screen. Cleared on an explicit "Leave Room" click. The entered display name is also remembered independently and pre-fills next time.
- **Connection watchdog** — status: **implemented**, not yet tested & functional. Addresses a reported real-world symptom: after a device sits backgrounded for a while, the Storyteller can end up thinking they're still connected while Players in the room (and new joiners) can't see them. Since there's no reliable way to distinguish "genuinely dead" from "just slow" via Trystero's public API, this detects the likely trigger (tab hidden for 15+ seconds) and does a full page reload on regaining focus, which is guaranteed to recover correctly because it reuses the reconnect path above rather than attempting a riskier in-place fix. The 15-second threshold is a guess and may need tuning after real testing.

## Current plans for full website

- Overall, the Storyteller can use the website to manage the game state and send night information to players, and Players can use the website to remind themselves of players' claims and send night choices to the Storyteller. The website is intended for in-person play, so public broadcasts or nomination support is not needed.
- The version for Players should be optimized to work with a mobile device (it should also work with a computer). UI should make tapping on icons easy and only require a keyboard where necessary. They can switch through multiple panels at the bottom of their screen. The default UI must use sufficient color contrast for players to easily read text and status at a glance, including in dim game rooms.
  - Status: **implemented**, not yet tested & functional. Bottom tab bar (`ui/tabs.ts`) shared by both roles. The default theme is now black/gold regardless of system light/dark preference. The Player's top-level "Players in this room" list was removed (Town Square, plus physically looking around the table, already serves that purpose) — see the Storyteller's "Lobby" button below for their equivalent.
  - **Fit-to-screen layout** — status: **implemented**, not yet tested & functional. Multiple rounds of real testing found this still didn't fit one screen: over half a desktop monitor's width went unused, the tab bar could scroll out of view, modals reset their scroll position on every interaction, and the room header/Script view/Grimoire padding all ate into limited vertical space. Fixed by: a fixed-height `#app` shell (internal scrolling confined to specific regions only, never the whole page); `#app`'s max-width raised from 720px to 1400px; modals (`ui/modal.ts`) now update their content in place (`updateModalContent`) instead of closing and reopening on every click, which is what was resetting scroll to the top; the Grimoire's seat circle and Script view scale with the available screen; the room header is now a single compact line (role + room code/name inline, smaller buttons, less padding) instead of a two-line block. Mobile viewports intentionally still rely on pinch-zoom rather than reflowing everything smaller.
- The Storyteller should have a "grimoire" panel where they can see all players' tokens arranged in a circle (matching the physical Town Square), tap any seat to open a popup with that seat's controls and a night-card composer built from clickable one/two-click buttons (not dropdowns) — number/text/Good/Evil quick buttons, a "Player" button that lets them tap any seat on the Grimoire to add it, a "Character" button opening a character grid picker, and preset autofill cards ("This is the Demon", "These are your Minions", "These characters are not in play", "You are") that pre-fill the obvious defaults from current seat/character data and can be edited or removed (e.g. for a Lunatic). A vacant seat's popup lists currently-connected-but-unplaced players to assign into that seat. Alive/dead (with a death shroud on the token) and vote-token state update for all players. Seat add/rename/remove/reorder now live inside this same popup (see "Seats panel," folded in below). Messages and night cards are the same thing — a per-seat message log/composer lives in the same popup (see "Messages and night cards are unified" below). The Storyteller also has a "Lobby" button showing everyone currently connected (seated and not).
  - Status: **implemented**, not yet tested & functional (`screens/host-room/grimoire-panel.ts`, `seat-modal.ts`, `lobby-modal.ts`). Some of the preset autofill cards have an unambiguous default (Demon reveal, Minions reveal, not-in-play bluffs, "You are" defaulting to the seat's own current character) and autofill fully; others ("This player is", "This character selected you", "Use your Ability?", "Make a Choice") have no single obvious default given the app doesn't know the exact ability being run, so they only pre-fill a text label / a generic choose-prompt. The seat popup is now a wide, two-column layout on desktop screens (game state on the left; messages + the night card composer on the right) rather than a narrow single-column dialog. The general notes textarea is no longer "pinned" anywhere — instead, each seat has its own private reminder note (e.g. "protected by Monk"), visible only to the Storyteller, alongside the general notes.
  - **Auto night-order checklist** — status: **implemented**, not yet tested & functional. Sits in a sidebar next to the Grimoire (two-column layout on wide/desktop screens). Generates the current script's first-night / other-nights order (plus synthetic "Minion info"/"Demon info" steps) from whichever characters are actually assigned to seats.
  - **Setup** (renamed from "Setup assistant") — status: **implemented**, not yet tested & functional. Matches the real Storyteller workflow: opens a character-grid menu where the Storyteller manually picks which characters are in play (with a running count against the suggested Townsfolk/Outsider/Minion/Demon split for the seat count) — the app only randomizes which *seat* gets which of the chosen characters, never which characters are chosen.
  - **Private ST-only audit log** — status: **implemented**, not yet tested & functional. Every sent card is timestamped and logged locally (persisted across ST reload too). Distinct from the newer per-seat message log (plain text exchange only — sent night *cards* stay in this audit log, not duplicated).
  - ~~Quick multi-target presets~~ — superseded by the composer's autofill preset cards; no longer a separate feature.
- ~~The Storyteller also has a "seats" panel...~~ — folded into the Grimoire's per-seat popup rather than a separate tab. Seats persist independently of connections; disconnecting doesn't remove a seat, and a vacant seat's popup is how a newly-connected device gets placed into it.
- Players should have a "night actions" panel where they can see their character, ability, and send & receive night cards with the storyteller.
  - Status: **implemented**, not yet tested & functional (`screens/join-room/night-actions-panel.ts`). Shows assigned character + ability, a full chronological feed (newest first), and reply controls for "choose a player"/"choose a character" prompts.
  - **Unread badge on the tab** — status: **implemented**, not yet tested & functional. Silent only (no sound/vibration).
  - **Messages and night cards are unified** — status: **implemented**, not yet tested & functional. There is no longer a separate "Messages" tab on either role. A Player can queue up several elements before sending — a "Got it" quick button, a chosen player (tapping "Player" opens the Town Square view as a picker, so they can choose with the same context — status, their own predictions — visible, per the request that this show Town Square rather than a bare list), or custom text — exactly like the Storyteller's own composer, rather than firing one at a time. - They should also have a "town square" panel where they can see all players in the game, arranged in a circle matching the Grimoire, their status (alive/dead — dead players show a shroud, matching the grimoire; vote token), as well as place a "prediction" (just set any character, via the same grid picker as the Grimoire, not a dropdown) and write information about them (in the middle, there would be a section showing the default amount of Townsfolk, Outsiders, Minions, and Demons).
  - Status: **implemented**, not yet tested & functional (`screens/join-room/town-square-panel.ts`). Tapping a seat opens a popup (matching the Grimoire's pattern) with that player's status, prediction picker, and a notes textarea, instead of an inline row. Predictions/notes are local-only scratch state (not persisted across reload, not sent anywhere). The panel live-updates while mounted. The script should fit all characters' names, tokens, abilities, and reminders, similar to when using the script tool to create a pdf.
  - Status: **implemented**, not yet tested & functional. `data/characters.ts` + `data/scripts.ts` hardcode all 22 Trouble Brewing characters (content hand-refined for accuracy — flavor text, player-facing night-info wording, keyword clarifications). Ability text shown inline; the character list flows through CSS columns spanning group boundaries, closer to the official script PDF's compact layout, plus the same 5–15+ player distribution table from the PDF at the bottom.
