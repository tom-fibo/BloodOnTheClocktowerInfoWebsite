## Current plans for full website

- Overall, the Storyteller can use the website to manage the game state and send night information to players, and Players can use the website to remind themselves of players' claims and send night choices to the Storyteller. The website is intended for in-person play, so public broadcasts or nomination support is not needed.
- The version for Players should be optimized to work with a mobile device (it should also work with a computer). UI should make tapping on icons easy and only require a keyboard where necessary. They can switch through multiple panels at the bottom of their screen. The default UI must use sufficient color contrast for players to easily read text and status at a glance, including in dim game rooms.
  - Status: **implemented**, not yet tested & functional. Bottom tab bar (`ui/tabs.ts`) shared by both roles. The default theme is now black/gold regardless of system light/dark preference (a night-game companion tool reads better dark than light by default) — light mode is still available behind `prefers-color-scheme: light` for anyone whose system explicitly asks for it.
  - **Fit-to-screen layout** — status: **implemented**, not yet tested & functional. First-round testing found the app didn't reliably fit one screen: over half a desktop monitor's width went unused, and the tab bar could scroll out of view. Fixed by making `#app` a fixed-height shell (`height: 100svh`, `overflow: hidden`) with internal scrolling confined to specific content regions only, so the room header and tab bar can never be scrolled away; `#app`'s max-width went from 720px to 1400px so desktop Storytellers actually get to use a wide monitor. The Grimoire's seat circle and Script view (see below) were both changed to scale with the available screen rather than a fixed size. Mobile viewports intentionally still rely on pinch-zoom rather than reflowing everything smaller — no `maximum-scale`/`user-scalable=no` lock in the viewport meta tag.
- The Storyteller should have a "grimoire" panel where they can see all players' tokens arranged in a circle (matching the physical Town Square), tap any seat to open a popup with that seat's controls and a night-card composer built from clickable one/two-click buttons (not dropdowns) — number/text/Good/Evil quick buttons, a "Player" button that lets them tap any seat on the Grimoire to add it, a "Character" button opening a character grid picker, and preset autofill cards ("This is the Demon", "These are your Minions", "These characters are not in play", "You are") that pre-fill the obvious defaults from current seat/character data and can be edited or removed (e.g. for a Lunatic). A vacant seat's popup lists currently-connected-but-unplaced players to assign into that seat. Alive/dead (with a 🪦 shroud) and vote-token state update for all players. Seat add/rename/remove/reorder now live inside this same popup (see "Seats panel," folded in below). A notes textarea's first line pins as a banner above the circle. Messages and night cards are the same thing — a per-seat message log/composer lives in the same popup (see "Messages and night cards are unified" below).
  - Status: **implemented**, not yet tested & functional (`screens/host-room/grimoire-panel.ts`, `seat-modal.ts`). Some of the preset autofill cards have an unambiguous default (Demon reveal, Minions reveal, not-in-play bluffs, "You are" defaulting to the seat's own current character) and autofill fully; others ("This player is", "This character selected you", "Use your Ability?", "Make a Choice") have no single obvious default given the app doesn't know the exact ability being run, so they only pre-fill a text label / a generic choose-prompt — the Storyteller completes them with the Player/Character buttons. Worth revisiting the exact semantics of these against the real app if the mapping feels off at the table. The circle now scales up to a large size on wide screens (`min(100%, 78vh, 760px)`) rather than a small fixed thumbnail.
  - **Auto night-order checklist** — status: **implemented**, not yet tested & functional. Moved to a sidebar next to the Grimoire (two-column layout on wide/desktop screens, since the Storyteller is assumed to be on a computer) rather than stacked below. Generates the current script's first-night / other-nights order (plus synthetic "Minion info"/"Demon info" steps) from whichever characters are actually assigned to seats.
  - **Setup** (renamed from "Setup assistant") — status: **implemented**, not yet tested & functional. Matches the real Storyteller workflow: opens a character-grid menu where the Storyteller manually picks which characters are in play (with a running count against the suggested Townsfolk/Outsider/Minion/Demon split for the seat count, and the Baron's +2 Outsider/-2 Townsfolk noted in the count itself once picked) — the app only randomizes which *seat* gets which of the chosen characters, never which characters are chosen. The old "Send Minion/Demon info" one-click button was removed; the same result is now reached via the composer's autofill preset cards instead.
  - **Private ST-only audit log** — status: **implemented**, not yet tested & functional. Every sent card is timestamped and logged locally (persisted across ST reload too).
  - ~~Quick multi-target presets~~ — superseded by the composer's autofill preset cards described above; no longer a separate feature.
- ~~The Storyteller also has a "seats" panel...~~ — folded into the Grimoire's per-seat popup (see above) rather than a separate tab, since seat management and character/status management are the same "click a seat" interaction. Seats persist independently of connections; disconnecting doesn't remove a seat, and a vacant seat's popup is how a newly-connected device gets placed into it.
- Players should have a "night actions" panel where they can see their character, ability, and send & receive night cards with the storyteller.
  - Status: **implemented**, not yet tested & functional (`screens/join-room/night-actions-panel.ts`). Shows assigned character + ability, a full chronological feed (newest first), and reply controls for "choose a player"/"choose a character" prompts.
  - **Unread badge on the tab** — status: **implemented**, not yet tested & functional. Silent only (no sound/vibration) — `ui/tabs.ts` shows a dot on the Night Actions tab until it's opened.
  - **Messages and night cards are unified** — status: **implemented**, not yet tested & functional. There is no longer a separate "Messages" tab on either role. A Player always has a "Got it" quick button plus a custom-text box right in Night Actions to send the Storyteller something unprompted (an acknowledgment, a choice they made, anything else) — internally this is just a card with one `text` element, sent over the same channel as before, so it slots into the same chronological feed as received cards rather than a separate log. The Storyteller's equivalent lives inside each seat's own popup (a small message log + quick-send box), replacing the old global Messages tab where you'd pick a player from a list first.
- They should also have a "town square" panel where they can see all players in the game, arranged in a circle matching the Grimoire, their status (alive/dead — dead players show a shroud, matching the grimoire; vote token), as well as place a "prediction" (just set any character, via the same grid picker as the Grimoire, not a dropdown) and write information about them (in the middle, there would be a section showing the default amount of Townsfolk, Outsiders, Minions, and Demons).

Predictions/notes are local-only scratch state (not persisted across reload, not sent anywhere). The panel now live-updates while mounted (roster/character changes reflect immediately, not just on next tab switch — this was a real gap in the previous round).
