## Night communication MVP (room + roster + private ST/Player messaging)

- Status: **functional**
- Scope: Storyteller hosts a room via a shareable code; Players join with a display name; everyone sees a live, ordered player roster; Storyteller can secretly message any one Player; a Player can secretly message only the Storyteller. Peer-to-peer via Trystero (WebRTC), no backend.
- Not yet done / explicitly deferred: offline/no-internet fallback, GitHub remote + Pages deployment (manual step, not yet performed) — this MVP is comms plumbing only; actual game content (characters, night order, votes, etc.) is covered under "Current plans for full website" below.
- **Persistent reconnect / seat reclaim** — status: **functional**. A per-room localStorage token is sent with `hello`; the Storyteller matches it back to the player's existing seat instead of creating a new one.
- **Storyteller disconnect resilience** — status: **functional**. The Storyteller's room state (seats, characters, script, per-seat messages, notes) persists to localStorage and restores on reload/crash — same-browser recovery only, not cross-device.
- **Auto-rejoin last session on reload** — status: **functional**. A reload (intentional or accidental) now re-navigates to whichever room screen (Storyteller/Player) this browser was last in, via a `localStorage`-saved `{screen, roomCode, selfName}` — the actual rejoin correctness still comes from the reconnect-token/host-state mechanisms above, this just gets the app to *try* rather than dumping the user at the landing screen. Cleared on an explicit "Leave Room" click. The entered display name is also remembered independently and pre-fills next time.
- **QR code join link** — status: **functional**. Storyteller's room header has a "QR" toggle encoding a join URL (`?join=CODE`); `join-setup` pre-fills the code from that URL. Manual code entry still works as before. Uses the new `qrcode-generator` dependency (see MAINTENANCE.md). First-round testing found the toggle button did nothing (a CSS specificity bug — a later `display: flex` rule silently beat the `.hidden` utility); fixed with a combined `.qr-container.hidden` selector.
- **Connection watchdog** — status: **functional**. Addresses a reported real-world symptom: after a device sits backgrounded for a while, the Storyteller can end up thinking they're still connected while Players in the room (and new joiners) can't see them. Since there's no reliable way to distinguish "genuinely dead" from "just slow" via Trystero's public API, this detects the likely trigger (tab hidden for 15+ seconds) and does a full page reload on regaining focus, which is guaranteed to recover correctly because it reuses the reconnect path above rather than attempting a riskier in-place fix. The 15-second threshold is a guess and may need tuning after real testing. Both roles now skip this auto-reload if a modal is currently open (`ui/modal.ts`'s `isModalOpen()`), and the Player side additionally skips it if there are unsent composer elements queued — so a reload never silently discards a night card the user was mid-way through composing.
- **Player-side stale-connection recovery** — status: **implemented**. Previously a Player stuck on the "Storyteller disconnected" banner had no way to recover short of manually reloading the tab, even after the Storyteller's own reload had already fixed things — `onStorytellerLeave` only showed the banner, nothing then re-checked the connection. The banner now also has its own "Refresh connection" button, and starts an 8-second timer that reloads automatically (same modal-open/pending-composer guard as above) if the roster hasn't come back by then.
- **Reopening the Lobby now resyncs every connected seat** — status: **functional**. `HostRoomHandle.resyncConnectedSeats()` re-broadcasts the roster and re-sends each connected seat's character assignment; `lobby-modal.ts` calls it every time the modal opens. Gives the Storyteller a low-cost way to nudge a Player's client (refreshing their "Your Character" section and the roster Town Square uses for its player picker) without needing a full reload.

- **Sent night card showed blank once delivered** — status: **fixed**. Root cause: `sendNightCard` stored the composer's element array *by reference* in the sent payload, the seat's message log, and (for a disconnected seat) the pending-delivery queue — but the seat-modal's Send button clears that same array in place (`composerElements.length = 0`) immediately afterward, since arrays are reference types. For an immediately-delivered card this happened to be harmless (the wire send had already serialized it), but a *queued* card for a disconnected seat, and the Storyteller's own message-log entry for any card, ended up empty once actually rendered. Fixed by copying the array (`[...elements]`) before storing/queuing it anywhere.
- **Player still saw "No character assigned yet" after rejoining until switching tabs** — status: **fixed**. Root cause was a listener registration-order race in `join-room/index.ts`: the Night Actions panel registers its own `onCharacterAssign`/`onNightCard` (to re-render) at mount time, which happened *before* `index.ts`'s own listeners (which update the actual shared `nightActionsState`) got registered — so an event arriving while that panel was already mounted (as it typically is right after rejoining, since it's the default tab) rendered using the not-yet-updated state, and nothing re-rendered it afterward. Fixed by registering `index.ts`'s state-updating listeners before `renderTabs()` mounts the initial panel, so they always run first.
- **Grimoire seat tokens could overlap** — status: **fixed**. `resizeCircleToFit()` (added to size the circle to available space) had no floor, so on a sufficiently cramped window it could shrink the circle below the point where adjacent tokens' fixed-width boxes started overlapping each other. Now enforces a seat-count-aware minimum (`minCircleSize()`, inverting `circular-layout.ts`'s own chord-length math for its `CIRCLE_RADIUS_PERCENT`) so two adjacent tokens are never closer than their own width plus a small gap — if that minimum is bigger than the space actually available, the circle now overflows and lets the page scroll to it rather than shrinking further into overlap.
- **Town Square summary text could sit under the bottom seat** — status: **fixed**. For an even seat count, one seat always lands exactly at the bottom of the circle (the true worst case for how far a token's box reaches downward — odd counts only ever get close, never exactly there); the summary line right below the circle didn't have enough clearance for that case. Added top margin to `.town-square-summary` sized for the worst case regardless of parity.
- **Script view wasted width on wide monitors** — status: **fixed**. `.script-columns` used `columns: 280px` (an ideal width, not a fixed one) — but the actual column count the browser settles on is also capped by how many `.script-group`s exist (4, each pinned to one column via `break-inside: avoid-column`), so on a wide monitor the browser computed room for more columns than there was content to fill, leaving them empty instead of stretching the ones in use — wasting horizontal space and forcing more text-wrapping (a taller layout) than necessary. Raised the ideal width to 420px so the browser settles on fewer, wider columns to begin with.

  - Status: **functional**. Bottom tab bar (`ui/tabs.ts`) shared by both roles. The default theme is now black/gold regardless of system light/dark preference.   - **Fit-to-screen layout** — status: **functional**. Multiple rounds of real testing found this still didn't fit one screen: over half a desktop monitor's width went unused, the tab bar could scroll out of view, modals reset their scroll position on every interaction, and the room header/Script view/Grimoire padding all ate into limited vertical space. Fixed by: a fixed-height `#app` shell (internal scrolling confined to specific regions only, never the whole page); `#app`'s max-width raised from 720px to 1400px; modals (`ui/modal.ts`) now update their content in place (`updateModalContent`) instead of closing and reopening on every click, which is what was resetting scroll to the top (this took two passes — the first only stopped the overlay itself from being recreated, but the card *inside* it is the actual scrolling element and was still a fresh, scrolled-to-top node each time; the fix now explicitly carries `scrollTop` over from the old card to the new one); the Grimoire's seat circle and Script view scale with the available screen; the room header is now a single compact line (role + room code/name inline, smaller buttons, less padding) instead of a two-line block. Mobile viewports intentionally still rely on pinch-zoom rather than reflowing everything smaller. Two further real-testing fixes: the Grimoire's header row (heading + Lobby/Setup/etc. buttons) had a large unwanted gap above it, caused by reusing the `.button-row` class (whose top margin belongs on the setup/landing screens, not next to a heading) — scoped an override for the Grimoire's two header rows. The seat circle's height was also a flat `78vh`-based guess that could still clip the bottom row of seats under the tab bar on some window shapes; it's now measured and sized dynamically in JS (`resizeCircleToFit()`, via `ResizeObserver`) against whatever space is actually left after the header/banners/notes, guaranteeing the whole circle is always visible without scrolling regardless of window size — except that it now also enforces a seat-count-aware minimum so tokens can't overlap, and will overflow into a scrollable page rather than shrink past that minimum on a truly cramped window.
