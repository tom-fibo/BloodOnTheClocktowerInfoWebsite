## Current plans for full website

- Overall, the Storyteller can use the website to manage the game state and send night information to players, and Players can use the website to remind themselves of players' claims and send night choices to the Storyteller. The website is intended for in-person play, so public broadcasts or nomination support is not needed.
- The version for Players should be optimized to work with a mobile device (it should also work with a computer). UI should make tapping on icons easy and only require a keyboard where necessary. They can switch through multiple panels at the bottom of their screen. The default UI must use sufficient color contrast for players to easily read text and status at a glance, including in dim game rooms.
  - Status: **implemented**, not yet tested & functional. Bottom tab bar (`ui/tabs.ts`) shared by both roles; reuses the existing light/dark CSS variables for contrast.
- The Storyteller should have a "grimoire" panel where they can see all players' tokens, as well as click any to easily send night cards (similar to how it works on botc.app - there should be a menu where they can send a number, a specific player, a specific character, "Choose a Player", "Choose a Character", [show a change in character], etc. They can also update state (alive/dead, vote token) which will update for all players — dead players show a shroud overlay on their token, matching the official app's visual convention. The storyteller should be able to prepare all information and then send it in one card.) They can also write a custom note (potentially with a way for a section of that note to also be shown in the main Grimoire view).
  - Status: **implemented**, not yet tested & functional (`screens/host-room/grimoire-panel.ts`). Composer supports all listed element kinds bundled into one card; alive/dead toggle shows a 🪦 shroud; character assignment is sent privately per-seat (never broadcast — see MAINTENANCE.md privacy section). Notes: only the note's first line is shown as a pinned banner — no separate rich "excerpt selection" UI. Known gap: a card combining *two* "choose" prompts only captures one response (see MAINTENANCE.md).
  - **Auto night-order checklist** — status: **implemented**, not yet tested & functional. Generates the current script's first-night / other-nights order (plus synthetic "Minion info"/"Demon info" steps) from whichever characters are actually assigned to seats.
  - **Randomized setup assistant** — status: **implemented**, not yet tested & functional. Uses the official Trouble Brewing 5-15 player distribution table, applies the Baron's +2 Outsider/-2 Townsfolk modifier when Baron is rolled, and randomly assigns to all current seats in one click.
  - **Private ST-only audit log** — status: **implemented**, not yet tested & functional. Every sent card is timestamped and logged locally (persisted across ST reload too).
  - **Quick multi-target presets** — status: **implemented**, not yet tested & functional. One button sends Minions their fellow evil team + Demon, and the Demon their Minions + 3 random not-in-play bluffs.
- The Storyteller also has a "seats" panel where they can control how many seats are in the game, and which player is in which seat (and rename players if needed). Players' town square panel would show these seats (and the names in them), but not other players. If a player disconnects, their seat remains active and retains information, so that if they reconnect, they can see all information that seat had (this depends on the persistent reconnect work above).
  - Status: **implemented**, not yet tested & functional (`screens/host-room/seats-panel.ts`). Add/remove/rename seats, reorder occupants via swap (↑/↓), connection status shown per seat.
- Players should have a "night actions" panel where they can see their character, ability, and send & receive night cards with the storyteller.
  - Status: **implemented**, not yet tested & functional (`screens/join-room/night-actions-panel.ts`). Shows assigned character + ability, full received-card history (newest first), and reply controls for "choose a player"/"choose a character" prompts.
  - **Unread badge on the tab** — status: **implemented**, not yet tested & functional. Silent only (no sound/vibration) — `ui/tabs.ts` shows a dot on the Night Actions tab until it's opened.
- They should also have a "town square" panel where they can see all players in the game, their status (alive/dead — dead players show a shroud, matching the grimoire; vote token), as well as place a "prediction" (just set any character) and write information about them (in the middle, there would be a section showing the default amount of Townsfolk, Outsiders, Minions, and Demons).
  - Status: **implemented**, not yet tested & functional (`screens/join-room/town-square-panel.ts`). Predictions/notes are local-only scratch state (not persisted across reload, not sent anywhere).
- Both Players and Storytellers should be able to see the script. The storyteller can also change the script. For now, having a pre-set selection hardcoded into the website is acceptable (e.g. json file with all characters and json file for each script of which characters it includes) — start with Trouble Brewing only. The script should fit all characters' names, tokens, abilities, and reminders, similar to when using the script tool to create a pdf.
  - Status: **implemented**, not yet tested & functional. `data/characters.ts` + `data/scripts.ts` hardcode all 22 Trouble Brewing characters; ability/flavor wording was written from memory of the official script and should be checked against a physical almanac before relying on exact phrasing at the table.
- Both Players and Storytellers can easily open a "detailed information" popup for each character (from all views - seeing it on the script, setting it to a player in town square or grimoire, or when mentioned in night information). This would show the character namem, token (using the circle texture with their icon, such as https://release.botc.app/resources/characters/tb/washerwoman_g.webp), their ability description, a "clarification" section (not on the app by default - this would say things like "Pair: Players sitting next to each other." to clarify keywords), flavor text, wiki link, and *what* information they would receive in the night (e.g. for the Chef, shows that they learn a number in the first night, usually 0 or 1, and nothing in subsequent nights). This should be designed to be openable on both Mobile and Desktop views (e.g. long press on mobile, on desktop hovering shows the name, ability, and clarification, and they can also open the full more info popup).
  - Status: **implemented**, not yet tested & functional (`ui/character-popup.ts`). Tap/click opens the full popup everywhere a character appears; desktop hover additionally shows a name/ability/clarification tooltip. Token images hotlink `release.botc.app` — a third party's asset host we don't control, so this could silently break if they change their URL scheme; worth revisiting if tokens stop loading.
